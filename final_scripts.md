## Сценарий №1 - регистрация, авторизация и просмотр профиля

1. Новый пользователь открывает страницу регистрации.
2. Система показывает регистрационную форму.
3. Пользователь вводит данные и нажимает кнопку "Зарегистрироваться".
4. Система проверяет корректность введенных данных.
5. Система создает аккаунт, выполняет вход и открывает страницу с учебными комнатами, если данные введены правильно.
6. Авторизованный пользователь открывает страницу своего профиля.
7. Система показывает имя пользователя и электронную почту.
8. Пользователь выходит из аккаунта и при последующем входе заходит по имени пользователя или электронной почте и паролю.
9. Система показывает сообщение об ошибке, если регистрационные данные некорректны.

## Сценарий №2 - создание закрытой учебной комнаты

1. Авторизованный пользователь открывает страницу с учебными комнатами.
2. Система показывает форму создания комнаты.
3. Пользователь вводит название новой комнаты.
4. Пользователь оставляет выключенным параметр "Публичная комната".
5. Пользователь нажимает кнопку "Создать".
6. Система проверяет введенное название и создает закрытую комнату.
7. Система назначает пользователя владельцем комнаты и автоматически формирует уникальный код приглашения.
8. Система открывает созданную комнату или показывает сообщение об ошибке, если введенные данные некорректны.

## Сценарий №3 - создание публичной учебной комнаты

1. Авторизованный пользователь открывает страницу с учебными комнатами.
2. Система показывает форму создания комнаты.
3. Пользователь вводит название новой комнаты.
4. Пользователь включает параметр "Публичная комната".
5. Пользователь нажимает кнопку "Создать".
6. Система проверяет введенное название и создает публичную комнату.
7. Система назначает пользователя владельцем, формирует уникальный код и добавляет комнату в общий список публичных комнат.
8. Система открывает созданную комнату или показывает сообщение об ошибке, если введенные данные некорректны.

## Сценарий №4 - присоединение к учебной комнате

1. Авторизованный пользователь открывает страницу с учебными комнатами.
2. Система показывает форму входа по коду и список публичных комнат.
3. Пользователь вводит код приглашения для входа в закрытую комнату или выбирает публичную комнату из списка.
4. Пользователь нажимает кнопку "Присоединиться".
5. Система проверяет существование выбранной комнаты и правильность кода приглашения.
6. Система добавляет пользователя в список участников комнаты.
7. Система открывает страницу выбранной комнаты.
8. Система не добавляет пользователя повторно, если он уже является участником комнаты.
9. Система показывает сообщение об ошибке, если комнаты не существует или код приглашения введен неправильно.

## Сценарий №5 - выход из учебной комнаты и её удаление

1. Участник комнаты открывает страницу учебной комнаты.
2. Система показывает информацию о комнате и доступные пользователю действия.
3. Участник комнаты нажимает кнопку "Выйти из комнаты".
4. Система удаляет пользователя из списка участников и возвращает его к списку комнат.
5. Владелец комнаты выбирает действие "Удалить комнату".
6. Система запрашивает подтверждение удаления комнаты.
7. Владелец комнаты подтверждает удаление.
8. Система удаляет комнату и связанные с ней данные, после чего возвращает владельца к списку комнат.
9. Система запрещает удаление и показывает сообщение об ошибке, если действие пытается выполнить пользователь, который не является владельцем комнаты.

## Сценарий №6 - работа с синхронным таймером Помодоро

1. Участник комнаты открывает страницу учебной комнаты.
2. Система показывает текущее состояние общего таймера.
3. Участник комнаты выбирает режим фокусировки на 25 минут или режим перерыва на 5 минут.
4. Участник комнаты запускает таймер.
5. Система начинает обратный отсчет и передает его состояние всем участникам комнаты через WebSocket-соединение.
6. Участники комнаты видят одинаковое оставшееся время без обновления страницы.
7. Участник комнаты останавливает или перезапускает таймер при необходимости.
8. Система сообщает всем участникам о завершении выбранного периода.
9. Система показывает сообщение о проблеме соединения и восстанавливает актуальное состояние таймера после повторного подключения.

## Сценарий №7 - работа с канбан-доской

1. Участник комнаты открывает канбан-доску внутри учебной комнаты.
2. Система загружает сохраненные карточки и показывает их в соответствующих колонках.
3. Участник комнаты нажимает на кнопку создания новой карточки.
4. Участник комнаты вводит название задачи и подтверждает создание.
5. Система добавляет карточку в начальную колонку и сохраняет её в базе данных.
6. Участник комнаты перемещает карточку в другую колонку после изменения состояния задачи.
7. Система сохраняет новое положение карточки и показывает его остальным участникам.
8. Участник комнаты удаляет карточку, которая больше не нужна.
9. Система показывает сообщение об ошибке, если название не введено или сохранить изменения не удалось.

## Сценарий №8 - обмен сообщениями в текстовом чате

1. Участник комнаты открывает текстовый чат внутри учебной комнаты.
2. Система загружает и показывает сохраненную историю сообщений.
3. Участник комнаты вводит текст нового сообщения.
4. Участник комнаты нажимает кнопку отправки.
5. Система сохраняет сообщение с указанием автора и времени отправки.
6. Система передает сообщение другим участникам через WebSocket-соединение.
7. Участники комнаты видят новое сообщение без обновления страницы.
8. Система не отправляет пустое сообщение и показывает ошибку, если соединение с сервером отсутствует.

## Сценарий №9 - сохранение и синхронизация данных между устройствами

1. Авторизованный пользователь создает учебную комнату и работает с её содержимым.
2. Система сохраняет профиль пользователя, список комнат, сообщения и карточки задач в базе данных.
3. Пользователь закрывает приложение или выходит из аккаунта.
4. Пользователь открывает веб-сервис на другом устройстве.
5. Пользователь входит в тот же аккаунт с помощью имени пользователя или электронной почты и пароля.
6. Система загружает профиль пользователя, список его комнат, историю сообщений и состояние канбан-досок.
7. Пользователь продолжает работу с ранее сохраненного состояния.
8. Система показывает сообщение об ошибке и предлагает повторить загрузку, если получить сохраненные данные не удалось.
